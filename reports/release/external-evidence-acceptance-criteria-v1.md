# External Evidence Acceptance Criteria v1

Status: Active (Signed)  
Owner: Program Governance + QA/RA

## Purpose

Define release-blocking acceptance criteria for external interoperability and scientific evidence bundles.

## Scope

- Interoperability campaigns (`reports/interoperability/*`)
- External scientific/clinical validation campaigns (`reports/clinical/*`, `reports/analytical/*`, `reports/pmcf/*`)

## Acceptance Criteria (Release-Blocking)

### 1) Minimum independent site count

- Interoperability evidence MUST include at least 2 independent external sites per protocol family (`DICOMweb`, `DIMSE`), and at least 1 external workflow-capable site (`MWL/MPPS`).
- Scientific campaign evidence MUST include at least 2 independent external sites for each active claim family.

### 2) Minimum dataset size

- Interoperability: each protocol family MUST include at least 30 executed positive-path cases and at least 20 negative-path fail-closed cases across participating sites.
- Scientific: each active quantitative claim MUST include at least 50 accepted observations per site, unless a stricter protocol-defined threshold exists.

### 3) Independent reviewer requirement

- At least 2 independent reviewers MUST sign each blinded/qualitative endpoint package.
- Any reviewer disagreement MUST include an adjudication record with rationale and signed disposition.

### 4) Hash and signing integrity requirement

- Every release-scope evidence bundle MUST publish SHA256 hashes for included artifacts.
- Every release-scope evidence bundle MUST include a cryptographic signature record generated by `tools/evidence_sign_verify.py`.
- Signature verification MUST pass for the final release evidence set before GO/NO-GO closure.

### 5) Provenance origin classification requirement

- Every traceability-linked evidence artifact MUST be classified as one of:
  - `synthetic`
  - `de-identified`
  - `external-independent`
- Missing origin classification is a release-blocking failure.

## Rejection Criteria

Evidence is rejected when any of the following are true:

- site-count threshold is not met,
- case-volume threshold is not met,
- reviewer signatures are incomplete,
- hash/signature verification fails,
- provenance origin class is missing or invalid,
- evidence artifacts contain template placeholders for release-scope rows.

## Verification Commands

- `python3 tools/evidence_sign_verify.py verify --bundle <signed_bundle.json>`
- `python3 tools/evidence_realism_lint.py --release-id RC-2026.02.12 --manifest reports/traceability/release-traceability-manifest-RC-2026.02.12.json`
