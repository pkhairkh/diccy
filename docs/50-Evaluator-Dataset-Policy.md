# Evaluator Dataset Policy and Synthetic Generator Guide

Status: **Baseline evaluator policy** (As of 2026-02-22)
Reference: `docs/10-Testing-Corpus-Fuzzing-Evals.md`

## 1. Policy requirements

- Evaluation artifacts must be PHI-safe by default.
- Use synthetic or de-identified datasets for demo and benchmark workflows.
- Do not commit patient identifiers to repository history, logs, or benchmark outputs.

## 2. Approved dataset sources

- In-repo deterministic corpus (`corpus/`).
- Synthetic fixtures generated by test builders in crate/unit tests.
- Explicitly reviewed external validation datasets referenced in release evidence docs.

## 3. Generator usage

Recommended baseline commands:

```bash
./tools/local_demo_end_to_end.sh
./tools/time_to_first_image.sh
./tools/fusion_perf_harness.sh
```

These commands use deterministic local fixtures and produce reproducible output artifacts under `reports/`.

## 4. Prohibited practices

- Uploading raw clinical studies with identifiers to shared CI logs.
- Using network fetch flows for ad-hoc datasets in release gating.
- Storing unredacted DICOM metadata exports in long-lived reports.
